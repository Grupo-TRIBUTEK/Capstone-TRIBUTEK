# Configuración de la conexión a PostgreSQL

En `backend/src/prisma/db.ts` se carga explícitamente el archivo `backend/.env` antes de crear el cliente PostgreSQL.

La variable requerida es:

```env
DATABASE_URL="postgresql://usuario:contraseña@localhost:5432/base_de_datos"
```

También se valida que `DATABASE_URL` exista. Si falta, el backend muestra un mensaje claro en lugar del error `Provide one binding input`.

Para verificar el cambio:

```bash
cd tributek/backend
npm run build
npm run start:dev
```

## Solución de errores en la conexión y autenticación

Durante las primeras pruebas del endpoint `POST /auth/login` se detectaron y solucionaron dos problemas.

### 1. Carga de `DATABASE_URL`

NestJS no carga automáticamente las variables definidas en `.env`. Por este motivo, el cliente PostgreSQL se estaba creando sin una URL de conexión válida y aparecía el error:

```text
Provide one binding input: binding, url, or pg
```

La solución fue cargar explícitamente el archivo `.env` en `db.ts` antes de crear el cliente PostgreSQL y validar que `DATABASE_URL` estuviera definida.

### 2. Serialización de valores `BigInt`

Una vez solucionada la conexión, el endpoint podía consultar correctamente el usuario y verificar su contraseña, pero al devolver la respuesta apareció el siguiente error:

```text
TypeError: Do not know how to serialize a BigInt
```

Esto ocurrió porque los campos `id` y `rolId` de PostgreSQL son tratados como `BigInt` por Prisma 8, y Express no puede serializar directamente estos valores en una respuesta JSON.

Se solucionó convirtiendo estos identificadores a `string` antes de devolver la respuesta:

```ts
return {
  mensaje: 'Usuario encontrado',
  usuario: {
    id: usuario.id.toString(),
    nombreUsuario: usuario.nombreUsuario,
    rolId: usuario.rolId.toString(),
  },
};
```

### Resultado de la prueba

Después de realizar las correcciones, el endpoint:

```text
POST /auth/login
```

fue probado mediante Postman utilizando un usuario de prueba y respondió correctamente:

```json
{
  "mensaje": "Usuario encontrado",
  "usuario": {
    "id": "2",
    "nombreUsuario": "admin",
    "rolId": "1"
  }
}
```

Esto confirma que la conexión entre NestJS, Prisma 8 y PostgreSQL funciona correctamente y que el proceso actual de autenticación puede encontrar al usuario y validar sus credenciales mediante Argon2.
